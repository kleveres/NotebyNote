# 1. Описание

## 1.1. Наименование

**NoteByNote** — веб-сервис для создания, хранения и совместного редактирования заметок с поддержкой папок и истории изменений.

## 1.2. Предметная область

Сервис позволяет пользователям вести личные заметки, раскладывать их по папкам, сохранять историю правок и открывать доступ к отдельным заметкам другим пользователям.

Основные объекты предметной области:

- **Пользователь** — участник сервиса с ролью «Пользователь» или «Модератор» (незарегистрированный посетитель считается «Гостем»).
- **Папка** — раздел пользователя для группировки его заметок (один уровень, без вложенности папок друг в друга).
- **Заметка** — основная запись пользователя, содержащая заголовок, текст, статус доступа и привязку к папке.
- **Версия заметки** — сохранённая копия заголовка и текста заметки до внесения правок, позволяющая просматривать историю изменений и возвращаться к прошлым вариантам.
- **Приглашённый пользователь** — пользователь, которому автор заметки открыл доступ на чтение (read) или редактирование (edit).
- **Тег** — метка для быстрого поиска и фильтрации заметок.

### 1.2.1. Ключевые требования к продукту

1. **Приватность по умолчанию:** новые заметки создаются со статусом «private» и видны только автору. Совместная работа возможна только после того, как автор откроет доступ конкретным пользователям (статус shared).
2. **История изменений:** при каждом сохранении изменений старый вариант заметки автоматически записывается в историю версий, чтобы автор мог в любой момент посмотреть прошлые правки или откатиться к ним.
3. **Модерация и безопасность:** личные заметки (private) не видны никому, включая модераторов. Как только заметка переводится в статус shared, она становится доступна модератору для проверки на нарушение правил сервиса. Дополнительно фиксируются IP-адреса регистрации и последнего входа для защиты от массовой регистрации ботов и несанкционированной передачи учётных записей.

# 2. Данные

Схема базы данных включает **7 таблиц**:

- основные: users, folders, notes, note_versions;
- справочник: tags;
- связующие: note_collaborators, note_tags.

## 2.1. Связи

- пользователи 1:N папки (владелец)
- пользователи 1:N заметки (автор)
- папки 1:N заметки
- заметки 1:N версии заметок
- пользователи 1:N версии заметок (автор правки)
- заметки M:N пользователи через note_collaborators (совместный доступ)
- заметки M:N теги через note_tags

## 2.2. Ограничения по элементам данных

### 2.2.1. users

Зарегистрированный пользователь системы.

| Поле | Тип | Ограничения |
| :--- | :--- | :--- |
| id | BIGSERIAL | Первичный ключ |
| nickname | VARCHAR(50) | Обязательное. Не пустое. Уникально |
| email | VARCHAR(255) | Обязательное. Уникально. Только нижний регистр: email = lower(email) |
| password_hash | VARCHAR(255) | Обязательное. Хранится только хеш пароля |
| role | VARCHAR(10) | Обязательное. ('user', 'moderator') по умолчанию 'user' |
| is_banned | BOOLEAN | Обязательное. По умолчанию FALSE |
| registration_ip | VARCHAR(45) | Обязательное. IP-адрес при регистрации |
| last_login_ip | VARCHAR(45) | Необязательное. IP-адрес последнего успешного входа |
| created_at | TIMESTAMP | Обязательное. По умолчанию now() |

Ограничения уровня таблицы:

- Уникальные индексы по nickname и email.
- Пароль проверяется приложением до хеширования (не менее 8 символов).
- С одного registration_ip допускается регистрация не более 3 учётных записей за 24 часа (проверяется приложением в транзакции).
- Заблокированный пользователь (is_banned = TRUE) не может войти в систему и выполнять изменяющие запросы.
- Индекс (registration_ip, created_at) — проверка лимита регистраций.

### 2.2.2. folders

Папки пользователя для группировки заметок (одноуровневые, без вложенности).

| Поле | Тип | Ограничения |
| :--- | :--- | :--- |
| id | BIGSERIAL | Первичный ключ |
| owner_id | BIGINT | Обязательное. Ссылается на users(id), ON DELETE CASCADE |
| name | VARCHAR(100) | Обязательное. Не пустое |
| created_at | TIMESTAMP | Обязательное. По умолчанию now() |

Ограничения уровня таблицы:

- UNIQUE (owner_id, name) — у одного пользователя не может быть двух папок с одинаковым названием.
- У одного пользователя не более 30 папок (проверяется приложением в транзакции).

### 2.2.3. notes

Актуальное состояние заметки.

| Поле | Тип | Ограничения |
| :--- | :--- | :--- |
| id | BIGSERIAL | Первичный ключ |
| author_id | BIGINT | Обязательное. Ссылается на users(id), ON DELETE CASCADE |
| folder_id | BIGINT | Необязательное. Ссылается на folders(id), ON DELETE CASCADE |
| title | VARCHAR(200) | Обязательное. Не пустое: length(trim(title)) > 0 |
| content | TEXT | Обязательное. Длина не более 50 000 символов |
| status | VARCHAR(10) | Обязательное. status IN ('private', 'shared', 'blocked'). По умолчанию 'private' |
| block_reason | VARCHAR(500) | Необязательное. Заполняется только при status = 'blocked' |
| current_version | INT | Обязательное. current_version >= 1. По умолчанию 1 |
| created_at | TIMESTAMP | Обязательное. По умолчанию now() |
| updated_at | TIMESTAMP | Обязательное. По умолчанию now(). updated_at >= created_at |

Допустимые переходы статуса заметки:

| Из | В | Кто и при каком условии |
| :--- | :--- | :--- |
| private | shared | Автор заметки (при выдаче доступа хотя бы одному приглашённому пользователю) |
| shared | private | Автор заметки (все записи из note_collaborators по этой заметке удаляются в той же транзакции) |
| shared | blocked | Модератор (с обязательным указанием block_reason) |
| blocked | shared | Модератор (после проверки/исправления; block_reason очищается) |

Ограничения уровня таблицы:

- согласованность статуса блокировки и причины (поля block_reason и blocked взаимосвязны).
- У одного пользователя не более 100 заметок (проверяется приложением в транзакции).
- Если указан folder_id, папка должна принадлежать author_id (проверяется приложением).
- В статусе blocked редактирование заголовка и текста, добавление приглашённых пользователей и возврат к прошлым версиям запрещены.
- Индекс (author_id, folder_id) — выборка заметок пользователя по папкам.
- Индекс (status, updated_at) — список заметок на проверку модератору.

### 2.2.4. note_versions

История изменений содержимого заметки.

| Поле | Тип | Ограничения |
| :--- | :--- | :--- |
| id | BIGSERIAL | Первичный ключ |
| note_id | BIGINT | Обязательное. Ссылается на notes(id), ON DELETE CASCADE |
| editor_id | BIGINT | Необязательное. Ссылается на users(id), ON DELETE SET NULL |
| version_number | INT | Обязательное. version_number >= 1 |
| title_prev | VARCHAR(200) | Обязательное |
| content_prev | TEXT | Обязательное |
| created_at | TIMESTAMP | Обязательное. По умолчанию now() |

Ограничения уровня таблицы:

- UNIQUE (note_id, version_number) — уникальность номера версии внутри одной заметки.
- Для одной заметки хранится не более 20 последних версий; при превышении лимита самая старая версия автоматически удаляется в той же транзакции. Ручное редактирование и выборочное удаление записей истории пользователем запрещено.

### 2.2.5. note_collaborators

Права совместного доступа к заметкам (связь M:N между notes и users).

| Поле | Тип | Ограничения |
| :--- | :--- | :--- |
| note_id | BIGINT | Обязательное. Ссылается на notes(id), ON DELETE CASCADE |
| user_id | BIGINT | Обязательное. Ссылается на users(id), ON DELETE CASCADE |
| permission | VARCHAR(10) | Обязательное. permission IN ('read', 'edit'). По умолчанию 'read' |
| granted_at | TIMESTAMP | Обязательное. По умолчанию now() |

Ограничения уровня таблицы:

- PRIMARY KEY (note_id, user_id).
- Нельзя добавить автора заметки в список приглашённых пользователей (user_id <> notes.author_id).
- Лимит: не более 15 приглашённых пользователей на одну заметку.
- Если у shared-заметки удаляется последний приглашённый пользователь, заметка автоматически возвращается в статус private в той же транзакции.

### 2.2.6. tags

Справочник тегов для фильтрации заметок.

| Поле | Тип | Ограничения |
| :--- | :--- | :--- |
| id | BIGSERIAL | Первичный ключ |
| name | VARCHAR(40) | Обязательное. Уникально в нижнем регистре: name = lower(trim(name)) и length(name) > 0 |

### 2.2.7. note_tags

Привязка тегов к заметкам (связь M:N).

| Поле | Тип | Ограничения |
| :--- | :--- | :--- |
| note_id | BIGINT | Обязательное. Ссылается на notes(id), ON DELETE CASCADE |
| tag_id | BIGINT | Обязательное. Ссылается на tags(id), ON DELETE CASCADE |

Ограничения уровня таблицы:

- PRIMARY KEY (note_id, tag_id).
- Не более 10 тегов на одну заметку.

## 2.3. Общие ограничения целостности

1. **Ссылочная целостность:** все внешние ключи обязательны к проверке; при удалении заметки её версии, привязки тегов и права доступа удаляются каскадно; при удалении папки все заметки внутри неё удаляются каскадно.
2. **Конфиденциальность приватных заметок:** у заметки со статусом private не может быть записей в note_collaborators; доступ к ней имеет только author_id.
3. **Неразрывность истории версий:** при каждом изменении title или content в notes предыдущее состояние сохраняется в note_versions, а current_version увеличивается на 1 в одной транзакции.
4. **Разграничение прав:** удалять заметку, менять её папку, теги и список приглашённых пользователей может только author_id; изменять заголовок и текст заметки — author_id или приглашённый пользователь с правом edit (кроме заметок в статусе blocked).
5. **Временные метки:** created_at и updated_at заполняются автоматически; updated_at обновляется при каждом изменении заметки и не может быть меньше created_at.

## 2.4. Транзакции

Все операции, затрагивающие несколько таблиц или требующие проверки конкурентных ограничений, выполняются в рамках транзакций БД с уровнем изоляции READ COMMITTED.

Для исключения взаимных блокировок (deadlock) во всех транзакциях соблюдается единый порядок захвата блокировок: сначала строка целевой заметки (notes), затем строка пользователя (users), затем связующие таблицы (note_collaborators, note_tags, note_versions).

| № | Операция | Шаги выполнения в транзакции |
| :--- | :--- | :--- |
| **T1** | Регистрация пользователя | 1) Проверить, что с данного registration_ip за последние 24 часа создано менее 3 учётных записей. 2) Проверить уникальность email и nickname. 3) Вставить запись в users с хешем пароля и IP-адресом регистрации. При нарушении уникальности — откат транзакции. |
| **T2** | Создание заметки | 1) Блокировка строки автора (users FOR UPDATE). 2) Проверить лимит (не более 100 заметок у пользователя) и принадлежность folder_id автору. 3) Вставить запись в notes (status = 'private', current_version = 1). 4) Привязать выбранные теги в note_tags (не более 10). |
| **T3** | Редактирование заметки с сохранением версии | 1) Блокировка строки заметки (notes FOR UPDATE). 2) Проверить, что заметка не в статусе blocked, а пользователь — автор или приглашённый участник с правом edit. 3) Скопировать текущие title, content и current_version в таблицу note_versions с указанием editor_id. 4) Обновить title, content, updated_at в notes и увеличить current_version на 1; если число записей в note_versions для этой заметки превысило 20, удалить самую старую версию. |
| **T4** | Возврат к прошлой версии | 1) Блокировка строки заметки (notes FOR UPDATE). 2) Проверить, что запрос выполняет автор заметки и статус не равен blocked. 3) Сохранить текущее состояние заметки в note_versions (чтобы откат также фиксировался в истории). 4) Записать данные из выбранной исторической ревизии в notes и увеличить current_version на 1; если число записей в note_versions превысило 20, удалить самую старую версию. |
| **T5** | Управление доступом к заметке | **Выдача доступа:** 1) Блокировка заметки (FOR UPDATE). 2) Проверить права автора, статус (<> 'blocked') и лимит (не более 15 приглашённых пользователей). 3) Добавить или обновить запись в note_collaborators. 4) Если заметка была private, перевести её в статус shared.<br>**Отзыв доступа / возврат в private:** 1) Блокировка заметки (FOR UPDATE). 2) Удалить запись конкретного участника (или всех участников при полном закрытии доступа) из note_collaborators. 3) Если в note_collaborators не осталось ни одного участника, перевести заметку в статус private. |
| **T6** | Модерация заметки и блокировка пользователя | **Блокировка заметки:** 1) Блокировка заметки (FOR UPDATE). 2) Проверить роль модератора и статус заметки (shared). 3) Перевести заметку в статус blocked с записью block_reason.<br>**Блокировка пользователя:** 1) Блокировка строки пользователя (users FOR UPDATE). 2) Установить is_banned = TRUE. |

# 3. Пользовательские роли

| Наименование | Ответственность | Количество |
| :--- | :--- | :---: |
| **Гость** | Просмотр стартовой страницы, регистрация и вход в систему | неограничено |
| **Пользователь** | Создание и управление своими папками; создание, редактирование и удаление заметок; просмотр истории изменений и возврат к прошлым версиям; фильтрация заметок по папкам, тегам и статусам; выдача и отзыв доступа (read / edit) другим пользователям; чтение и редактирование заметок, к которым открыт доступ | неограничено |
| **Модератор** | Просмотр всех заметок в статусах shared и blocked и списка пользователей с данными об IP-адресах входа; блокировка заметок с обязательным указанием причины; снятие блокировки; блокировка и разблокировка учётных записей нарушителей | 1–5 |

В рамках одной заметки пользователь может находиться в одной из контекстных ролей:

- **автор заметки** — управляет заметкой, её статусом, списком приглашённых пользователей, тегами и откатом версий;
- **приглашённый пользователь с правом edit** — может просматривать заметку, историю её изменений и редактировать текст и заголовок (с записью новой версии от своего имени);
- **приглашённый пользователь с правом read** — может только читать заметку и просматривать историю её изменений.

# 4. UI / API

## 4.1. UI

1. **Авторизация и регистрация:**
   - формы входа и регистрации с проверкой вводимых данных на стороне клиента;
   - сохранение пользовательских настроек интерфейса (светлая/тёмная тема) в localStorage.
2. **Рабочее пространство пользователя:**
   - боковая панель со списком папок пользователя и фильтрами («Все заметки», «Общие со мной»);
   - панель фильтрации списка заметок по папке, тегам, статусу (private, shared, blocked) и поиску по заголовку;
   - отображение сводной статистики (количество заметок и папок пользователя).
3. **Редактор заметки:**
   - создание и редактирование заголовка, текста и набора тегов;
   - индикатор статуса заметки (private, shared, blocked с выводом причины блокировки);
   - окно «История изменений» со списком прошлых версий (номер, дата, автор правки) и кнопкой «Восстановить версию» для автора;
   - окно «Доступ» для приглашения пользователей по никнейму с выбором права (read или edit), изменения прав и закрытия общего доступа (возврат в private).
4. **Панель модератора:**
   - раздел, доступный только пользователям с ролью moderator;
   - список всех заметок со статусами shared и blocked с фильтрацией;
   - кнопки блокировки заметки (с вводом причины) и снятия блокировки;
   - список пользователей с отображением IP-адресов регистрации и последнего входа и кнопкой блокировки/разблокировки учётной записи.

| GET | /api/moderator/notes | Список всех заметок в статусах shared и blocked | Модератор |

| POST | /api/moderator/notes/{id}/unblock | Снятие блокировки с заметки | Модератор |
| GET | /api/moderator/users | Список пользователей с IP-адресами регистрации и входа | Модератор |
| POST | /api/moderator/users/{id}/ban | Блокировка или разблокировка учётной записи | Модератор |

Общие требования к API:

- Все изменяющие запросы проверяют авторизацию и права доступа.
- Ошибки возвращаются в едином JSON-формате `{ "code": "...", "message": "..." }` со стандартными HTTP-кодами:
  - 400 — ошибка валидации входных данных;
  - 401 — пользователь не авторизован или указаны неверные учётные данные;
  - 403 — недостаточно прав доступа или учётная запись заблокирована;
  - 404 — запрашиваемая заметка, папка или пользователь не найдены;
  - 409 — конфликт данных или нарушение бизнес-ограничений (занятый email/никнейм, превышение лимита регистраций/заметок/папок, попытка редактирования заблокированной заметки).

# 6. Тестирование

Для проверки корректности работы системы применяются модульные (Unit) и интеграционные тесты (стандартный пакет testing, testify и net/http/httptest на тестовой базе данных PostgreSQL).

Проверяемые сценарии:

- **Регистрация и авторизация:** валидация данных, уникальность email и nickname, ограничение на количество регистраций с одного IP за сутки, запрет входа для заблокированных пользователей (is_banned = TRUE).
- **Работа с папками и заметками:** уникальность названий папок в рамках пользователя, привязка заметок к папке и их каскадное удаление при удалении папки, соблюдение лимитов.
- **История изменений и транзакции:** атомарность сохранения предыдущей версии в note_versions при редактировании заметки, корректный расчёт current_version, восстановление выбранной версии.
- **Совместный доступ и статусы:** переходы private ↔ shared ↔ blocked, автоматический возврат в private при удалении последнего приглашённого пользователя, запрет редактирования в статусе blocked, проверка изоляции private-заметок от других пользователей и модераторов.
- **Фильтрация и права доступа:** корректность фильтрации заметок по комбинации параметров (папка, тег, статус, поиск) и возврат корректных HTTP-кодов ошибок (400, 401, 403, 404, 409).

Тестовые данные: набор пользователей (включая модератора и заблокированного пользователя), папок, тегов и заметок во всех статусах (private, shared, blocked) с историей версий.
